🌳 canopy

A pool of git worktrees for agentic coding sessions

Get Started View on GitHub

About canopy

canopy manages a pool of git worktrees so agent sessions — Claude Code, Codex, or anything else you point it at — each get their own isolated checkout instead of colliding in one working tree.

A single locked state.json tracks who holds each worktree, whether that holder is still alive, and whether the worktree is clean. Claiming, releasing, pruning stale sessions, and destroying worktrees for good are all first-class commands — and lifecycle hooks can wire claim/release straight into a session's start and stop, with no manual steps.

Key Features

🌲 Worktree Pool

Reuses idle worktrees or grows a new one on demand, up to a configurable max — no more manually juggling git worktree add for every parallel session.

🔒 Locked, Durable State

A single flock-protected state.json tracks every claim, so concurrent sessions never race each other for the same worktree.

💓 Live/Stale Detection

Every claim records its holder's PID. If that process dies without releasing, canopy knows — and prune reclaims it automatically once it's clean.

🪝 Agent Lifecycle Hooks

Ships with Claude Code and Codex hook scripts (plus a one-command installer) that claim on session start and release on session stop — no manual bookkeeping.

🧹 Safe Cleanup

prune reclaims stale-and-clean worktrees back to the pool; destroy permanently removes one, gated behind explicit flags for unmerged branches or uncommitted changes.

🐚 Manual Drop-In

canopy enter <path> drops a shell straight into any worktree for hands-on inspection, without touching its claim.

Installation

Two supported install paths: go install for anyone with a Go toolchain, or a curl-to-install script for everyone else. Linux and macOS, amd64 and arm64 — no Windows.

Option 1: go install

go install github.com/nexus-lab-org/canopy/cmd/canopy@latest

Installs a canopy binary to $(go env GOPATH)/bin (typically ~/go/bin) — make sure it's on your PATH.

Option 2: curl-to-install script

curl -fsSL https://raw.githubusercontent.com/nexus-lab-org/canopy/main/install.sh | sh

Downloads the prebuilt binary matching your OS/architecture from the latest GitHub Release and installs it to /usr/local/bin (if writable) or ~/.local/bin.

Verification:
canopy init inside a git repo, then canopy claim --holder my-session and canopy status.

Agent Hooks Setup

canopy ships hook scripts that claim a worktree when an agent session starts and release it when the session stops, so you never run claim/release by hand. Requires jq on PATH. Wire them up with one command:

git clone https://github.com/nexus-lab-org/canopy.git
cd canopy
./hooks/install.sh

This edits your user-level hook config — never a project-level one, so a cloned repo can never smuggle in its own hook commands just by being opened.

./hooks/install.sh

Wires ~/.claude/settings.json and ~/.codex/hooks.json ($CODEX_HOME/hooks.json) in one pass.

./hooks/install.sh --claude

Wires SessionStart/SubagentStart to claim.sh and Stop/SubagentStop to release.sh in ~/.claude/settings.json only.

./hooks/install.sh --codex

Same wiring, in ~/.codex/hooks.json only. Confirm your installed Codex version supports hooks.json first.

The installer is idempotent — safe to re-run — and reversible:

./hooks/install.sh --uninstall
Crash fallback:
If a session crashes and its Stop hook never fires, the claim isn't lost forever: canopy tracks the holder's PID, so canopy status reports it stale once that process dies, and canopy prune reclaims it automatically if the worktree is clean.

See hooks/README.md for the full payload-field reference and why user-level wiring matters.

Usage

Commands

Command What it does
canopy init Sets up the worktree pool for the current repo
canopy claim --holder <id> Hands you an idle worktree, or grows a new one, up to --max
canopy release --holder <id> Frees a worktree back to the pool (--force if the holder looks dead)
canopy status Lists every worktree with its holder, live/stale, and clean/dirty state (--json available)
canopy prune Reclaims stale-and-clean worktrees back to the idle pool
canopy destroy <path> Permanently removes a worktree (--include-unlanded/--include-dirty to override safety checks, --all-idle for bulk)
canopy enter <path> Drops a shell into a worktree for manual inspection, without touching its claim

Quick Example

Claim, work, release:
canopy claim --holder my-session → work in the printed path → canopy release --holder my-session
